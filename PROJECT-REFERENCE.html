1. Overview & Tech Stack

Audited 2026-07-16 directly from source code (not from README/ARCHITECTURE docs). Package name: promtify v0.1.0 — an AI UI-prompt library SaaS: curated prompts + one-click AI code generation + video courses, sold via tiered plans.

Core Framework

  • Next.js 16.2.1 (App Router, reactCompiler: true)
  • React 19.2.4 + React DOM
  • TypeScript 5, strict via tsconfig
  • Tailwind CSS v4 (via @tailwindcss/postcss)
  • shadcn/ui + Radix primitives (21 ui components)

Backend / Data

  • Neon serverless Postgres (@neondatabase/serverless, HTTP driver)
  • Drizzle ORM 0.45 + drizzle-kit migrations
  • better-auth 1.5 (email/password + Google + GitHub)
  • Anthropic SDK (Claude, primary) + OpenAI SDK (fallback)
  • Stripe 20 + Razorpay 2.9 (dual payment providers)
  • Resend (email) · Vercel Blob (storage)

Frontend Libraries

  • Zustand 5 — 3 stores (auth-modal, generator, ui)
  • TanStack React Query 5 — provider wired
  • react-hook-form + zod 4 — auth forms
  • framer-motion 12 AND motion 12 (both installed — duplicate)
  • hls.js — Mux HLS video in hero
  • sonner toasts · next-themes dark mode · lucide-react icons
  • react-markdown + remark-gfm — blog/markdown rendering

Infra

  • Vercel hosting (vercel.json, subdomain wildcard)
  • GitHub Actions — deploy-staging.yml / deploy-production.yml
  • 3 DB environments: dev / staging / production (3 drizzle configs)
  • pnpm 11 package manager
  • @upstash/ratelimit + redis installed but never used in code

3. Subdomain Routing — src/proxy.ts

Next.js 16 middleware (new proxy.ts convention). Runs on every request except _next/static, _next/image, favicon.ico, public, docs/promptship.

Flow per subdomain

  • admin.* — API paths pass through → no session cookie? redirect to app.*/login?callbackUrl=… → otherwise rewrite /x → /admin/x (maps into (admin)/admin/ route group). Role check happens later in layout/API, not in proxy.
  • app.* — /login /signup /verify and /api/* always pass through; everything else requires the ps.session_token (or __Secure-ps.session_token) cookie else redirect to /login.
  • root domain — logged-in user hitting / → redirect to app.*/dashboard; /admin* → redirect to admin subdomain; app-only routes (/dashboard /prompts /generate /learn /history /settings) → redirect to app subdomain; all else (marketing) passes.

Note: proxy only checks cookie presence, not validity — real validation happens server-side via better-auth in layouts/APIs.

10. AI Generation Module — src/lib/ai/

Active pipeline

  1. index.ts → generateCode(options) — options: promptText, framework, style, animationLevel, darkMode, borderRadius, primaryColor, customInstructions
  2. prompts/system-prompts.ts → buildPrompt() — assembles the full prompt
  3. Primary: providers/claude.ts — claude-sonnet-4-20250514, max_tokens 4096 (older model — Claude 5 family is current)
  4. Fallback on error: providers/openai.ts — gpt-4-turbo (legacy model)
  5. Returns: code, tokensInput/Output, latencyMs, provider, model → persisted to generations
Dead code in this module: providers/template-generator.ts (rich prompt builder using technicalSpecs jsonb) and templates/{base,react,flutter,html}.ts are never imported by any route or component. They look like an abandoned v2 of the generation pipeline for the template system.

18. ⚠️ Issues & Incomplete Work Found During Audit

1. Payments not functional end-to-end. No checkout initiation route; both webhook handlers are TODO stubs. Buying/upgrading cannot complete → tiers/credits never update automatically.
2. Env var name mismatch. Code reads EMAIL_FROM; .env.local/.env.example define FROM_EMAIL. Emails (when wired) would fall back to default sender.
3. bcryptjs is a devDependency but imported by the production route /api/admin/setup and scripts/create-admin.ts. On a prod install without devDeps this route crashes. Move to dependencies (or drop the route post-setup).
4. Email + Storage modules are orphaned. Resend and Vercel Blob helpers exist but are never invoked (no welcome email on signup, no upload UI in admin forms).
5. Rate limiting missing. @upstash/ratelimit + redis installed with env vars but no limiter anywhere — /api/generate is unprotected beyond credits.
6. Old AI model IDs. claude-sonnet-4-20250514 and gpt-4-turbo are outdated; costUsd is hardcoded '0'.
7. Free-tier credits inconsistency. TIER_CREDITS.free=5 but users.credits defaults to 0 and nothing grants/resets credits.
8. Both framer-motion and motion installed (same library, old + new name). 4 files use framer-motion, 1 uses motion/react — consolidate to motion.
9. /api/admin/setup live in prod guarded only by a header key; recommended to remove after bootstrap.
10. proxy.ts admin gate checks cookie presence only — role enforcement relies on layouts/APIs (currently OK, but layout must never skip the check).

20. 🎯 Target Architecture Plan (reviewed 2026-07-17)

Architecture review for the product pivot: template store (code / Figma / AI-prompt templates, free + paid, granular access) now; courses, AI editing, and a seller marketplace later. Also fixes the two operational pain points: local subdomain auth and admin security.

20.1 Root cause: why auth breaks on localhost

The session cookie is host-only in dev. lib/auth/index.ts:58 sets cookie domain: undefined when the root domain contains "localhost". A cookie set while logging in on app.localhost:3000 is therefore never sent to admin.localhost:3000 or localhost:3000 — so cross-subdomain login, role redirects, and the admin portal all fail locally while working in production (where .promtify.dev is shared). Safari additionally doesn't resolve *.localhost at all.

Fix — use a real wildcard dev domain so all three environments behave identically:

The 5-min cookieCache also means role/tier changes take up to 5 min to propagate — acceptable, but know it.

20.2 Admin security hardening

CRITICAL — mass-assignment at signup: role, tier, credits are declared as better-auth additionalFields without input: false. better-auth accepts additional fields from the sign-up request body unless input is disabled — meaning a crafted POST /api/auth/sign-up/email with {"role":"admin"} could self-provision an admin. Fix immediately: add input: false to all three fields (they are only ever set server-side / by webhooks).

20.3 Entitlements — the core model for the template business

The requirement — "some users get all access, some one template, some one full category (e.g. all Figma templates), free templates for everyone, payment plans decided later, courses/AI/marketplace as add-ons" — cannot be expressed by the current single users.tier column. The scalable answer is an entitlements table: one row = one grant of access. Pricing/packaging then becomes pure configuration — any future plan (bundle, single sale, subscription, promo, marketplace purchase) just creates entitlement rows, and the access check never changes.

-- New tables (Drizzle migration)
entitlements (
  id, user_id FK,
  scope        enum: 'all' | 'category' | 'template' | 'course' | 'feature',   -- feature = ai_generate, marketplace_sell…
  scope_id     text NULL,          -- category_id / template_id / module_id; NULL for 'all'
  source       enum: 'purchase' | 'subscription' | 'admin_grant' | 'promo' | 'marketplace',
  order_id     FK NULL, expires_at timestamptz NULL,   -- NULL = lifetime; set for subscriptions
  revoked_at   timestamptz NULL, created_at,
  UNIQUE (user_id, scope, scope_id)
)

// lib/access/index.ts — THE single gate, used by every API route and UI element
export async function canAccessTemplate(userId: string | null, t: Template) {
  if (t.isFree) return true;
  if (!userId) return false;
  return await hasEntitlement(userId, [
    { scope: 'all' },
    { scope: 'category', scopeId: t.categoryId },
    { scope: 'template', scopeId: t.id },
  ]); // one indexed query; expires_at > now(), revoked_at IS NULL
}

20.4 Paid asset delivery — never through /public

Anything in public/ is downloadable by URL-guessing. Paid template files (code zips, .fig files, prompt packs) must live in private storage.
  1. Store paid files in Vercel Blob with access: 'private' (the orphaned lib/storage.ts finally gets its job) — or Cloudflare R2 if egress cost matters later.
  2. Single endpoint: GET /api/templates/[id]/download?file=… → session → canAccessTemplate() → issue short-lived signed URL (60s) → record row in template_downloads (analytics + abuse detection).
  3. Free templates can serve through the same endpoint (uniform code path, still counted).

20.5 Purchase flow (provider-agnostic, plans pluggable later)

UI "Buy" → POST /api/checkout { productId }        ─ product = {kind: all_access|category|template|course, scopeId, prices}
        → Stripe Checkout (USD) / Razorpay (INR)    ─ metadata: { userId, productId }
        → webhook (signature-verified, idempotent by event id)
        → INSERT payments row + INSERT entitlement rows for the product
        → user refreshes → access live everywhere (one source of truth)

This fills the two TODO-stub webhooks with exactly one job each: translate a paid event into entitlement rows. A products config table (or typed config file at first) maps sellable SKUs → entitlement grants, so pricing experiments never touch access logic. Subscriptions set expires_at = period end; renewal webhooks extend it; cancellation simply lets it lapse.

20.7 Maintainability guardrails

  • Structural subdomain rewrites: replace the hand-maintained appOnlyRoutes list in proxy.ts with prefix rewrites (root→/(marketing) paths only, app.*→app pages, admin.*→/admin/* — the admin pattern applied to all three). New pages then route correctly with zero proxy edits (today /templates and /upgrade are already missing from the list).
  • One domain helper (config/site.ts already close): every URL built from NEXT_PUBLIC_ROOT_DOMAIN; grep-ban hardcoded domains.
  • Tests where regressions hurt: vitest units for proxy.ts (host+path+cookie → decision table), lib/access (entitlement matrix), webhook handlers (event → entitlement rows, idempotency). These three files ARE the business.
  • Keep the single-app monolith. Entitlements + structural rewrites remove the reasons it hurts; splitting apps now would only multiply auth/deploy surface.
